# 表形式の標準書

実務の標準書は本文より表であることが多い。

```
| No | 章 | 節  | 分類       | 規定内容                        | 区分 | 重要度 | 備考 |
|---:|---:|-----|------------|---------------------------------|------|--------|------|
|  1 |  3 | 3.2 | 完全性     | 画面項目には項目IDを付与すること | 必須 | 高     |      |
```

行をそのまま連結すると規定文が壊れ、標準書自身が持っている章・節・分類・区分・
重要度も捨ててしまう。表は「列の役割を読む」ところから始める。

## 1. 列の役割を判定する

ヘッダ行の各セルに次の語が含まれるかを見る。上から順に当て、
1つの役割につき1列だけ割り当てる。

| 役割 | ヘッダに含まれる語 |
|---|---|
| `rule`（規定内容） | 規定内容, 規定, 記述内容, 標準内容, チェック内容, ルール, 基準内容, 内容 |
| `chapter` | 章番号, 章 |
| `section` | 節番号, 節, 条項, 項番 |
| `category` | 分類, カテゴリ, カテゴリー, 観点, 対象 |
| `rule_type` | 必須区分, 強制力, 区分, 種別 |
| `severity` | 重要度, 重大度, 優先度, レベル, ランク |
| `no` | no, №, 番号, 通番 |
| `note` | 備考, 補足, メモ, 注記 |

判定の条件:

- **役割を特定できた列が3つ以上**あること。少ないと本文の行を誤ってヘッダと判定する。
- **`rule` 列が特定できていること。** 規定内容の列が分からない表は、
  どのセルが規定なのか決められない。読み違えるより連結して本文として扱うほうが安全。
- 12文字を超えるセルはヘッダ候補から外す。長いセルは見出しではなく本文。

**判定できなかった列は無視する。列名を推測して意味を与えない**（必須原則 9）。
「レベル」が重要度なのか階層なのか分からないなら、使わない。

## 2. 1枚のシートに表が複数ある

標準書には「記載例の表」と「レビュー観点の表」が並んでいることがよくある。
**最初の表のヘッダを全行へ当ててはいけない。**

```
（シート上段）記載例の表:  | 項目 | OK例 | NG例 |
（シート下段）観点の表:    | No | 観点 | 確認内容 | 重大度 |
```

上の表のヘッダを下の表に当てると、「NG例」の列を規定内容として読むことになり、
標準書が「やってはいけない」と書いた文が規定として抽出される。

行が上から下へ並ぶ前提で、**次のヘッダ行が現れる手前までを1つの表**とみなし、
表ごとに自分のヘッダを使う。表と表の間の見出し行や空行は、その表の規定内容の列が
空になるので後段で自然に落ちる。

## 3. 区分列の値を規範レベルへ写す

上から順に当てる。**並び順に意味がある。**

| 値に含まれる語 | 規範レベル |
|---|---|
| 条件付き必須, 条件付必須, 条件付き, 条件付 | `Conditional Mandatory` |
| 禁止, 不可, NG | `Prohibited` |
| 必須, MUST, 強制 | `Mandatory` |
| 推奨, SHOULD, 原則 | `Recommended` |
| 任意, MAY, 参考 | `Optional` |

「条件付き必須」を先に見るのは、「必須」が部分一致で先に当たってしまい、
条件の存在が消えるのを防ぐため（必須原則 5）。

**本文に明示的な禁止表現があれば、区分列より本文を優先する。**
区分列が「必須」でも本文が「〜してはならない」なら `Prohibited`。
禁止の取りこぼしは影響が大きい（必須原則 7）。

## 4. 重要度列の値を Severity へ写す

| 値に含まれる語 | Severity |
|---|---|
| 重大, 致命, 最高, Critical, A, S | `Critical` |
| 高, High, B | `High` |
| 中, Medium, C | `Medium` |
| 低, 軽微, Low, D | `Low` |

大文字小文字を潰さない。A / B / C / D / S といった1文字の記号を区別する必要がある。

## 5. 区分列が無く、重要度列だけある表

「観点 / 確認内容 / 重大度」のようなレビュー観点表には、区分列が無いことがある。
本文にも「〜すること」のような規範表現が現れない。

この場合、**重要度が付いている行は規定として扱う**。標準書がその行に重要度を
与えているのは、レビューで確認する対象として挙げているということ。

強さは書かれていないので `Mandatory` とし、判定根拠は
`重要度列:高` の形で残す。本文の規範表現から判定したものと区別できるようにする。

## 6. 章・節の列

行が自前で章・節を持っているなら、**見出しの追跡結果よりそちらを優先する**。
見出しの追跡は推測を含むが、列の値は標準書の記載そのもの。

- 章: 「第3章」→ `3`。それ以外は記載のまま。
- 節: 「3.2.1」形式ならそのまま。それ以外は記載のまま。

数字に直せない値を無理に解釈しない。「三章」とあれば「三章」のまま残す。

## 7. 分類列

分類列が [`classification.md`](classification.md) 9節の分類名そのもの
（「完全性」「セキュリティ」など）を書いている場合は、**そのまま使う**。

語彙一致に任せると、分類名が語彙表に無いために標準書の分類が捨てられ、
本文から別の分類が付いてしまう。標準書が自分で分類しているものを、
こちらの語彙表の都合で上書きしない。

分類名でない値（「画面項目」など）が入っている場合は、その値を
語彙一致の入力として使う（規定文より優先）。

## 8. 表の1行が長い規定を含む場合

規定内容の列に複数の文が入っていることがある。通常どおり `。` で文に分け、
それぞれを規定候補として扱う。「ただし」で始まる文は直前の規定の例外に付ける
（STEP 3 と同じ）。

体言止め（「型が一致」「命名規則に準拠」）が多いのも表の特徴。
質問文化は [`conversion-rules.md`](conversion-rules.md) 9節のサ変名詞の扱いに従う。
